# Valen-0.8B 训练耗时与 PR #39 对比记录

记录日期：2026-10-26；时间均为 UTC+8。

本次使用单机 **8 张 H200**，以 `shared_state` 模式完成非视频数据的两阶段 SFT：Warmup 155 步，联合全参数 SFT 766 步，**总耗时 1 小时 58 分 16 秒**。两阶段均完整跑完各自的一个 epoch；总耗时包含初始化、数据加载、阶段切换、编译和 checkpoint 保存，不包含排队及依赖环境准备。

本记录同时归档 [PR #39](https://github.com/Valen-Team/Valen/pull/39) 引出的历史耗时核查、FLA 消融和视频解码实验。PR 的约 1.2 小时联合训练耗时来自短跑外推，不能作为完整训练的实测值，也不能直接据此比较 L20Z 与 H200 的性能。

截至记录日，PR #39 已关闭，未合并；本文件保留相关测试的条件和结果。

## 2. 本次完整训练的数据与配置

从原训练清单中仅移除含视频输入的记录，保持剩余记录内容、顺序和分组。没有复制图像资源。

| 数据 | 图文记录 | 纯文本记录 | 总记录数 | QA 数 |

联合训练包含 Choice 771,136 题、Noul 345,155 题、Score 170,620 题。Warmup 使用原 10% 子集中过滤后保留的数据；它不是联合阶段之外新增的训练数据。

每次前向的 state 上限不是全局 batch size；训练按 token 预算累积梯度，实际每步 state 数可变。联合阶段平均约 1,286 个 state/步。

Mixer 宽度 256、层数 2、token hidden dimension 16、channel hidden dimension 1,024，随机种子为 42。图像预处理的像素预算范围为 65,536–262,144。优化器为 AdamW，weight decay 为 0.01。联合阶段主参数使用 FP32，backbone 计算使用 BF16。

软件环境为 PyTorch 2.6.0+cu124、CUDA 12.4、cuDNN 9.1、Transformers 5.4.0、FlashAttention 2.7.4.post1、Triton 3.2.0、FLA / fla-core 0.4.2、causal-conv1d 1.5.4。每个 GPU rank 均确认启用了：

- 语言标准注意力和视觉注意力的 `flash_attention_2`。
- 全部 18 层线性注意力的 FLA Gated Delta Rule。
- `FusedRMSNormGated` 和 CUDA causal-conv1d。

该环境的 PyTorch 使用 CXX11 ABI=0。首次尝试因预编译 causal-conv1d wheel 的 ABI 不兼容而在预检阶段退出，没有执行训练更新；随后使用同一 PyTorch 环境从源码编译 1.5.4，并通过三个算子的有限值前向、反向预检。依赖编译时间不计入下表。

单节点配置为 16 CPU、128 GiB 主机内存。每个 rank 只保留其原有 `epoch_shard` 对应的数据，保持全局索引、分片顺序和样本不变，以降低主机内存需求；这不等同于 PR 中合并多道问题。

| 阶段或统计范围 | 步数 | 实测秒数 | 换算耗时 |
| --- | ---: | ---: | --- |
| Warmup 训练循环 | 155 | 657.04 | 10 分 57 秒 |
| 联合 SFT 训练循环 | 766 | 6,275.05 | 1 小时 44 分 35 秒 |
| 两阶段训练循环合计 | 921 | 6,932.09 | 1 小时 55 分 32 秒 |
| 完整 pipeline，包括加载、切换、最终保存及退出 | — | 7,096.49 | **1 小时 58 分 16 秒** |

本次 pipeline 于 16:51:43 启动，18:50:00 结束，调度任务状态为 `Succeeded`。循环耗时已经包含循环内的数据处理和周期性保存；完整 pipeline 还包含循环之外的工作。

联合阶段累计处理 397,929,687 个 compute token，完整循环平均约 156.97 state/s、205.08 QA/s。平均每步约 8.19 秒；去除首步后的步耗时中位数为 6.30 秒，最后 100 步平均 7.02 秒。均值包含编译、周期性保存等波动，中位数不能直接乘以步数作为完整耗时。

联合阶段所有 rank 的 PyTorch 峰值 allocated 显存最大值为 **37.85 GiB**，不等于 `nvidia-smi` 显示的全部显存占用。联合阶段共保存 77 次 checkpoint，平均 8.00 秒/次、累计约 616 秒。最终 checkpoint 为 step766，约 9.55 GiB，包含训练状态。最后 30 步平均 loss 为 0.2762；本次未评测模型准确率，不据此判定性能或收敛质量。

## 4. 与历史训练、PR 估计的耗时对照

| 阶段 | 历史 32 × H200，含视频，完整循环实测 | PR：8 × L20Z，无视频、重新分组，短跑外推 | 本次 8 × H200，无视频、原分组，完整循环实测 |
| --- | --- | --- | --- |
| Warmup | 67 步；16 分 33 秒 | 预计 124 步；约 5 分钟 | 155 步；10 分 57 秒 |
| 联合 SFT | 325 步；7 小时 30 分 25 秒 | 预计 616 步；约 1.2 小时 | 766 步；1 小时 44 分 35 秒 |
| 两阶段合计 | 训练循环合计 7 小时 46 分 58 秒 | 两段估计相加约 1 小时 17 分钟，PR 称含启动 | 训练循环合计 1 小时 55 分 32 秒；完整 pipeline 1 小时 58 分 16 秒 |
| 单步耗时口径 | 联合循环平均 83.15 秒/步 | 联合稳定步骤约 4.4 秒/步 | 联合循环平均 8.19 秒/步；步耗时中位数 6.30 秒 |

PR 报告的环境为 PyTorch 2.10.0+cu128、cuDNN 9.10、Transformers 5.14.1、FlashAttention 2.8.3、FLA 0.4.2。其时间由 40 个 Warmup 步和 150 个联合步骤外推，并描述了早期编译造成的慢步骤。**本次没有得到 PR 同等环境、同等分组、同等数据的完整复现实验，因而不能给出 H200 与 L20Z 的严格加速比。**

PR 直接报告的测量窗口为联合 150 步共 1,352 秒、Warmup 40 步共 81 秒，另有联合约 100 秒、Warmup 约 75 秒的启动开销。其约 4.4 秒是稳定步骤耗时；第 101–150 步包含保存和偶发慢步骤的平均耗时约 6.0 秒。这些口径也应与完整循环均值区分。

历史训练包含 240,000 条视频记录，占全部 state 的 19.6%；视频贡献 229,957,240 个视觉 token，占图像与视频视觉 token 总量的约 69.6%。历史联合阶段每步最慢 rank 的数据准备等待平均为 10.60 秒，且四节点使用 Socket 通信并禁用 IB。其数据处理、视觉负载和通信条件均不同于本次单节点非视频训练。

历史日志还报告线性注意力快速路径缺失。因此，耗时差异与线性注意力实现、视频预处理、视觉 token 量、多机通信和数据分组均有关；本组实验没有逐项测量它们对完整 epoch 的独立贡献，不能将总耗时变化全部归因于其中一个因素。

## 5. PR 引出的受控算子与解码测试

### 5.1 仅替换 Gated Delta Rule 的消融

在单机 8 × H200 上，使用相同的 PyTorch、Transformers、初始 Mixer 和缓存输入，仅将 18 层线性注意力的 Gated Delta Rule 替换为 FLA 0.4.2。标准注意力始终使用 FlashAttention2；RMSNorm 和 Conv1d 保持原实现。每种负载先执行 1 个预热步骤，再测量 3 个优化步骤，取每步跨 rank 最大耗时的中位数。

| 缓存负载 | 原 PyTorch GDR | FLA GDR | 计算步骤加速比 | 原 / FLA 峰值 allocated 显存 |
| --- | ---: | ---: | ---: | ---: |
| 图文 + 文本：1,315 state、1,656 QA、522,522 token | 20.847 秒/步 | 5.924 秒/步 | **3.52×** | 52.99 / 34.62 GiB |
| 含视频混合负载：931 state、1,220 QA、519,373 token | 18.685 秒/步 | 5.614 秒/步 | **3.33×** | 53.33 / 36.11 GiB |

以上不包含视频解码、输入预处理和 checkpoint I/O；首次 Triton 编译也不计入稳定步骤。首个图文前向的全局 loss 绝对差约为 1.13e-4，所有测试组合的梯度均为有限值；这不是长训练数值等价或模型质量的验证。

这组消融只测 GDR 的替换。本次完整训练另外启用了 CUDA causal-conv1d 和 FusedRMSNormGated，因此其端到端结果应单独记录；本次没有继续拆分这两个算子的独立收益。

### 5.2 视觉 Conv3d 快路径核查

PR 提到了部分 PyTorch 2.9 / cuDNN 组合下视觉 patch embedding 的慢 Conv3d 路径。本地使用原 PyTorch 2.6 / cuDNN 9.1，对 1,024、3,840、16,384、65,536 个 patch 分别测试 contiguous 和 `channels_last_3d` 布局，均观察到 cuDNN 路径，**未复现 `aten::slow_conv_dilated3d`**。

因此，没有证据表明该回退是历史训练环境的实际瓶颈。PR 对其他版本的描述不应当直接套用到本环境；本地未重测那些版本。

### 5.3 视频 CPU 解码与短程端到端测试

对 16 个视频各采样 16 帧，使用相同帧索引。每个视频、每种解码器执行两次，下表使用第二次的耗时：合计列对 16 个视频求和，中位数列在这 16 个耗时之间取中位数。

| 解码方式 | 16 个视频耗时合计 | 单视频中位耗时 | 合计耗时加速比 |
| --- | ---: | ---: | ---: |
| torchvision | 13.128 秒 | 0.554 秒 | 1.00× |
| PyAV 按索引采样 | 6.039 秒 | 0.258 秒 | **2.17×** |

16 个视频的采样帧逐像素相同；另外 3 个完整编译样本的 token IDs、attention mask、视觉类型、视频 pixel values 和 grid 均一致。

另做了每个解码器 3 步的混合负载端到端短测：

| 解码设置 | 第 1 步 | 第 2 步 | 第 3 步 |
| --- | ---: | ---: | ---: |
| torchvision | 34.020 秒 | 54.983 秒 | 20.709 秒 |
| PyAV，失败时回退 torchvision | 18.956 秒 | 15.562 秒 | 11.234 秒 |

这组端到端测试按 torchvision → PyAV 的固定顺序运行，有首次遇到形状时的 Triton 编译和缓存逐渐预热，且 PyAV 分支共发生 3 次回退。24 个 rank/step 的 token 和 grid 签名均匹配。其步骤耗时不能作为解码器独立加速比，也不能用于外推完整视频训练时长；2.17× 仅适用于上面的 CPU 解码短测。
